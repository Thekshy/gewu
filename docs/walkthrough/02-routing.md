# 02 · 路由设计：从意图分类到执行策略

> 路由回答的问题不是「用户想干什么」，而是「这条消息该交给哪条执行路径、带什么策略」。
> 实现在 internal/agent/routing（P9 从编排域拆出的独立域，只依赖 LLM 的 Chat 能力）。

## 为什么路由是第一道工序

五条执行路径的成本差一个数量级：直答一次检索一次生成；深研四路检索加综合；办理流
要跨多轮收集槽位。路由错一题，后面全错——所以它值得单独做一个域、三层防御。

## cascade：三级级联（默认模式）

```
L0 规则快路径（毫秒、零成本、置信 1.0）
  └─ 办理强动词 + 明确办理动作 → transaction；并存咨询词 → hybrid
L1 小模型五类概率分布（flash）
  └─ 输出 {"scores": {五类概率}}，双阈值 + margin 判定
L2 主模型仲裁（few-shot，只吃 L1 落灰度区的少量流量）
  └─ 仍不确定 → factual + flagship（不自由发挥、不反问阻断）
```

三个关键设计：

**1. 概率分布而非单 label。** L1 输出五类概率而不是 argmax 后的单个标签，路由质量
的判断权从模型移回代码：双阈值（top1 ≥ 0.80 直接采信；< 0.55 不相信 L1）+ margin
（top1−top2 ≥ 0.15，小于则视为「类别纠缠」升级 L2）。阈值是编译期常量保证确定性；
平局按固定类别序取先，解析与排序均可复现。

**2. refusal 安全网。** 拒答是代价最高的误路由（直接拒绝服务）。实测 flash 会把
「我的情况符合转专业条件吗」高置信误判为 refusal——所以问题带办理强动词或校园领域
实体词却判 refusal 时，不采信，强制降入灰度区走 L2 复核。**这一条是被真实误路由
教出来的**：小模型对否定/拒答类指令的遵从不可全信，要代码级守卫兜底。

**3. L2 兜底方向是「转通用链路 + 提高档位」而不是猜。** 灰度区未决时走 factual +
flagship 模型——宁可走贵而通用的路，不做窄路硬猜（误入办理流/误拒答都更糟）。

## agent-first：把意图塌缩成执行策略

cascade 的五分类（factual/research/transaction/hybrid/refusal）把「业务意图」当成
一次性前置决策——hybrid 本身就是组合意图的补丁，误路由会锁死后续路径。agent-first
把分类空间塌缩为三条**执行策略**：

```
refusal → 固定拒答（安全护栏，不可塌缩）
direct  → 一次知识检索即可回答（便宜链路）
agent   → ReAct 引擎自主组合工具（flagship，全工具集）
```

关键取向：**不确定时 fail-open 到 agent，而不是猜错窄路**。agent 多花一点 token
可以自己纠正，误入窄路则整轮错误。hybrid 补丁类别在 agent-first 下自然消失——
agent 天然处理「办理 + 咨询」组合意图。

## 决策包：路由的输出不只是 label

`RouteDecision` 携带处理策略（FillPolicy 集中维护）：

| 字段 | 语义 | 消费方 |
|---|---|---|
| Route | 执行路径 | pipeline 分发 |
| Toolset | 最小权限工具子集（transaction 八件套） | ReAct 工具表收窄 |
| ModelTier | small / standard / flagship | 各分支模型档位 |
| PreRAG | 是否前置检索 | 直答/深研 |
| Layer/Confidence/Reason | 判定层级与置信 | route 事件（可观测） |

路由产出策略、下游照单执行——分类与执行解耦，是后面五段式管线思考（[05](05-tool-scaling.md)）
的雏形。

## 为什么三套实现并存

- **cascade** 是主链路（成本/准确均衡）；
- **classic**（旧单次五分类）保留为回退基线——路由改动需要 A/B 对照时它就是控制组；
- **agent-first** 是面向 agent 时代的方向验证。

三种模式一个入口 `Decide`，评测口径不变（route 事件标签兼容），切换只是一个环境变量。

## 边界与已知短板

- L1 依赖 flash 的概率输出质量，温度 0 下仍有非确定性（同题多次跑结果会漂）——
  评测口径必须按「失败集 ⊆ 已知 flaky 集」判定，见 [06](06-engineering.md)；
- 规则快路径的正则是枚举出来的高置信 case，新领域语料进来需要维护（刻意只收
  「几乎不可能错」的模式，宁缺勿滥）。
