# ADR-0009:微服务退役与单体模块化

日期:2026-09-06 · 状态:已接受 · 关联:0001(服务拆分边界)、0002(Milvus/PG 向量)、0003(Redis Streams MQ)、0007(预算分布式计量)、0008(SQLite→PG)

## 背景

P0~P5 完成了单体 → 微服务(1 网关 + 5 gRPC 服务)的迁移,以 26/26 逐题 PARITY
契约测试证明拆分不改变行为;P6~P7 起主线回到单体补齐主流能力(级联路由、父子块、
ReAct、记忆、查询改写),微服务冻结在 P5 形态。

本项目的目的是学习与展示。微服务形态的设计/拆分/对照已经完成并留有完整证据
(PARITY-MS.md、六服务源码、评测报告),继续维护双形态只剩成本没有收益:

- **量级不匹配**:单实例用户量、15 文档/60 chunks 的知识库,远未触及分布式收益的触发线;
- **主线专注**:P6+ 的能力演进(路由/检索/Agent Loop)全部落在单体,微服务侧不再演进;
- **双形态税**:每个行为改动都要维护两份实现与两套评测,且无对照价值(PARITY 已证毕)。

## 决策

**退役微服务,收口为模块化单体。**退役不是删除学习成果,原则是"先吸收、后删除":

### 能力吸收(删除前落地)

| 能力 | 来源 | 落地 |
| --- | --- | --- |
| 办理流程状态跨重启持久化 | conversation 服务(PG) | **P8-1**:`SessionStore` 接口双后端,SQLite 版(data/sessions.db)缺省启用,重启续办验证 + 28/8 无回归 |
| 存储后端可换(PG/Milvus) | rag 服务(store_pg/vec_milvus) | **不吸收**:15 文档量级远未触及触发线;接口已收敛,历史实现按 git 复活 |

### 删除(阶段 3,tag `pre-ms-removal` 锚点)

cmd/{gateway,orchestrator,conversation,generate,tool,rag}、internal/services/、
internal/svcbase/、proto/、pkg/gen/、buf 配置、Dockerfile.svc、compose 的六服务与
pg/redis/milvus/monolith 编排、Makefile 微服务目标、DemoModeNote 残留、
eval/compare_search.py;go mod tidy 后 pgx/milvus/go-redis/zap/grpc/protobuf
直接依赖全部消失(约 -16,500 行 + 36 项依赖)。

### 单体模块化固化(阶段 4)

- 显式模块地图与依赖规则:`agent → rag/llm/business`(经 Retriever/LLMer/Tools 接口),
  反向禁止;business 只经 agent.Tools 触达;支撑域无业务依赖;cmd/server 只做装配;
- 零依赖 lint 守护 `make lint-arch`(go list + grep),进 CI;已反向验证拦截有效性;
- 观测小吸收:X-Trace-Id(uuid v4 零依赖)贯穿响应头/gin 日志/[agent] 日志。

## 后果

**正向**:单一形态,行为演进零对照税;go.mod 回到"gin + sqlite + openai 兼容客户端"
的最小面;模块边界有机器守护,模块化单体不是"一锅粥"。

**负向/风险**:失去服务级隔离与独立扩缩容——在当前量级下不是真实需求;若未来
触发线到来(chunk 万级/多副本/多写入方),按 git 历史与本 ADR 复活分布式形态:
服务边界见 ADR-0001,PG/Milvus 存储实现见 tag `pre-ms-removal` 的
internal/services/rag/store_pg.go、vec_milvus.go,行为契约以 docs/PARITY.md 为准。
