# ADR-0006 业务系统归属 tool 服务；user 服务端注入

日期：2026-09-04　状态：已采纳（边界 P0 定，迁移 P4 落地）

## 决策

- venues/bookings/leave_tickets 由 tool 服务独占托管（存储见 ADR-0008），
  `CallTool` 是业务系统的**唯一入口**：未知工具/越权/缺参在进入业务前拦截
  （文案逐字，PARITY §10）。
- 过渡：P2 期间编排进程内联冻结 internal/business（同库文件），P4 换成
  tool RPC——两步走让会话状态与工具执行分别验收，缩小回归面。
- **敏感参数 `user` 只从 gRPC metadata（x-user）读取**，由 gateway/orchestrator
  从 role 派生（demo-{role}），模型与客户端不可传——与单体「chat 请求体
  无 user 字段」的语义一致，防越权伪造。

## 后果

- `/api/business/reset|overview` 由 gateway 直转 tool（评测断言依赖）。
- 编排侧槽位解析需要场馆数据（parseVenue/normVenueID）——tool 暴露
  ListVenues/VenueByName 只读 RPC。
