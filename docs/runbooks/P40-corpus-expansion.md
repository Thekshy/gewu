## 1. 目标 / 非目标

**目标**
- 语料 15 篇/60 块 → **~200 篇/2000~3000 块**，覆盖大学全阶段（招生→在读→毕业
  →深造/就业），六类文档形态（办法/细则/FAQ/通知公告/办事指南/简表）。
- **干扰结构**：每个主题 ≥2 篇近邻；~15 个主题带版本对（2024 旧版 vs 2026
  现行）；既有主题间交叉点显式建文档（如转专业 × 学分认定）。
- **评测重新有分布**：挑战子集基线 recall < 0.95（区分度达成的定义）、全量
  recall 落在 0.70~0.95、精排 ablation 增益可测（挑战子集 NDCG ≥ +3pp）。
- 一致性可审计：bible + 自检脚本 + 抽检记录 + 挑战题人审清单全部留档。

**非目标**
- 不动检索/精排/改写的任何代码路径（本票是语料与评测集的票；检索参数若需
  调优另立，§5）。
- 不做万级语料（WeKnora 产品化量级），不追求覆盖全部高校制度门类。
- 不搬真实高校文档、不做 OCR/PDF 解析管线（虚构生成不依赖外部文档源）。
- 论文文稿更新只出数字清单，不改正文（§5 挂账）。
- run_eval（端到端）只回归不设门：新语料下 agent 行为变化记录不拦截。

## 2. 设计与实现

### 2.1 P40-1：setting bible + 生成管线 + 语料入库（先行票，独立可发）

**bible（`docs/corpus-bible.md`）**——注意不能放 `data/corpus/`（ingest 对
`corpus/*.md` 全量 glob，bible 会被当语料误入库）。骨架八节：

1. 校情：钱塘大学，虚构公办本科，学生规模、学院名录（含存量 15 篇出现过的
   全部学院/部门）；
2. 组织架构：部门名录与职责口径（教务处/学工部/研究生院/图书馆/后勤/校医院/
   团委/就业指导中心/财务处/保卫处/国际交流处…）；
3. 学年时间线：两学期制、学期起止、考试周、假期（以存量 0006-calendar 为准
   反向收编）；
4. 学籍数字口径：学制、毕业学分要求、绩点制满分、学位授予条件（以 0001/0002/
   0003/0013 等存量数字为准）；
5. 奖助金额体系：奖学金档次/助学金/贷款上限（以 0004 为基准扩展）；
6. 收费与金额口径：学费档次、各项工本费（校园卡 15 元等存量数字）；
7. 文档规范：六类形态的定义与写作模板（办法=章节条款体；细则=细粒度条款；
   FAQ=问答体；通知=带文号与年份；指南=流程步骤体；简表=表格体）+ 文号
   规则（钱教〔YYYY〕NN 号）+ 版本对写作要求：**旧版正文须明示「本文件已被
   钱教〔2026〕XX 号替代」、新版须带施行日期**（给 embedding/rerank 词面
   抓手——frontmatter 的 updated 不参与嵌入拼装，区分信号必须在正文里）；
8. 存量事实台账：15 篇逐篇抽取的全部硬事实（数字/日期/部门/条件），生成时
   遇冲突以存量为准、修订 bible。

**主题矩阵（~200 篇的分配）**：

| 域 | 篇数 | 主题（每主题 2~6 篇，含既有主题的近邻变体） |
|----|------|------|
| 教务教学 | ~45 | 选课退课、重修、考试纪律、补缓考、成绩管理、培养方案、课堂考勤、教评 + 既有转专业/辅修/学分认定的细则与 FAQ |
| 学籍管理 | ~25 | 注册、学籍异动、休学复学、退学、保留学籍、转学 + 既有转专业/学业预警的 FAQ 与年度通知 |
| 毕业深造 | ~20 | 毕业审核、学位授予、毕业离校、考研支持 + 既有毕业论文/保研的细则与通知 |
| 奖助贷勤 | ~25 | 助学金、助学贷款、勤工助学、困难认定、学费减免 + 既有奖学金的评定细则与 FAQ |
| 学生管理 | ~20 | 纪律处分、学生申诉、综合素质测评 + 既有请假/体测的细则与通知 |
| 后勤生活 | ~25 | 食堂、体育场馆、心理咨询、保险、校园安全、实验安全 + 既有宿舍/校园卡/校医院/医保的指南与 FAQ |
| 国际交流 | ~10 | 国际暑期项目、外语等级考试 + 既有交换项目的细则与 FAQ |
| 就业档案 | ~15 | 就业指导、三方协议、档案转递、户口迁移、证明开具 |
| 图书馆信息化 | ~15 | 校园网、一网通办、信息公开 + 既有图书馆的各分区规则、借阅 FAQ、开放时间公告 |

干扰结构三要求（生成时按主题 checklist 核对）：近邻 ≥2 篇且**文档类型必须
不同**（防同形态互抄）；版本对集中在 ~15 个高查询频次主题；交叉点文档显式
引用被交叉文档（如转专业细则引用 0002 学分认定）。

**文档密度**：新增文档每篇 60~150 行（分章分节、含附表），对齐真实制度文档；
存量 15 篇保持 27~30 行原样。

**生成管线（三步，执行会话内完成）**：
1. 生成：主模型逐篇生成，输入 = 主题 × 类型 + bible 相关节 + 同主题已有篇目
   摘要（防重复防矛盾）；分域分批，每批过一个自检再续下一批；
2. 自检：新增 `scripts/corpus_check.py`——① frontmatter 完备性
   （title/source/updated）与编号连续性；② 硬事实比对（金额/日期/部门名/
   校名正则抽取，对 bible 台账白名单比对，未知数字报冲突清单）；③ 同主题
   篇目间 n-gram 重叠率报警（阈值调试定，防近邻变互抄）；④ 命名规范
   （`NNNN-slug.md`，corpus 目录只允许该形态文件）；
3. 入库：`make ingest` 零改动（glob 自动收新文件，`rag_upsert_doc` 幂等）；
   可先 `NO_EMBED=1` 干跑验证切块与块数，再全量嵌入。

**成本预估**：生成主模型调用 ~250~400 次（含重试，长文档输出）；embedding
~3000 块一次性（GLM，成本可忽略）；总计单会话可完成，分域提交。

### 2.2 P40-2：评测集分化 + 重跑 + ablation（依赖 2.1，可同票连发）

**评测集三层（~135 题，`dataset.jsonl` 加 `tier` 字段，向后兼容缺省
must_pass）**：
- **必过（~60）**：存量题保留；**gold 复核**（新增脚本或并入 corpus_check）：
  每题在新语料上跑检索，若出现语义上更应命中的新文档 → gold 增补或题目
  移入挑战层，复核报告留档；
- **挑战（~60）**：近邻区分 ~35（题面须使 ≥2 篇近邻都进语义邻域、gold 唯一）、
  版本时效 ~10（指向现行版，须能在 2024/2026 并存下区分）、跨文档交叉 ~15；
  出题由执行会话主模型起草，**人工审定为硬门禁**——防「LLM 生成语料 + LLM
  出题 + LLM 判分」循环论证，审定的判定理由（为何 gold 唯一）逐题留档；
- **黄金（~15）**：深度 multi-hop，须组合 2~3 篇才能答全（如「受学业预警的
  学生能否申请转专业并转出课程学分如何认定」串 0014+0001+0002）。

**重跑口径**：`make retrieval-eval` 4 象限 ablation（rewrite × rerank 全开/
单关/双关）× 2 轮，分 tier 出分；报告落 `eval/reports/` 沿用现有 schema 加
tier 汇总节。观察项（Q6）：3000 块下召回池与 fan-out 的行为变化记录在报告
结论里，若全量 recall 破 0.70 下界先调检索参数再判语料回炉。

**验收数字（三条硬门）**：
1. 挑战子集基线（no_rewrite + no_rerank）recall@6 ≤ 0.95——**仍满分即近邻
   密度不足，回炉加干扰文档**；
2. 全量 recall@6 ∈ [0.70, 0.95]——低于下界说明语料/检索失配（先参数后语料）；
3. rerank 在挑战子集 NDCG@6 增益 ≥ 3pp——精排价值可测，论文 ablation 证据
   成立。

## 3. 风险与守卫

| 风险 | 守卫 |
|------|------|
| LLM 批量生成自相矛盾（数字/时间线/部门） | bible 硬约束 + corpus_check 数字白名单比对 + 每域抽 1 篇人工全读留档 |
| 近邻文档互相抄（重叠率过高，干扰项失去干扰性） | 六类文档类型差异化模板 + n-gram 重叠报警 + 同主题已有篇目喂入生成上下文 |
| 语料扩了评测仍满分 | 验收门禁第一条即此；回炉策略=加密近邻 + 增版本对 |
| recall 掉出下界（< 0.70） | 分批扩（先 ~100 篇插桩测一轮再续）；检索参数重检在先 |
| 存量题 gold 失效（新语料出现更应命中文档） | P40-2 gold 复核脚本 + 报告，增补或降级有痕 |
| 挑战题循环论证（出题与判分同源） | 挑战题人工审定硬门禁，判定理由逐题留档 |
| ingest 误收非语料文件 | bible 放 docs/；corpus_check 校验 corpus 目录内文件命名与形态 |
| 长文档切块行为漂移（150 行 vs 存量 30 行） | NO_EMBED 干跑先验块边界与块数；入库后抽 3 篇人工看切缝 |
| 生成/嵌入耗时与成本失控 | 分域分批提交；EMBED_BATCH 既有退避；全量预估见 2.1 |
